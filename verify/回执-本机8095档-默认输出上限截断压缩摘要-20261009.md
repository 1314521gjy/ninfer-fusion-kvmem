# 回执 · ④ 8095 档：引擎默认输出上限 8192 截断客户端压缩摘要 ⇒ 会话涨过 `--max_context` 后每轮干净 400

> 日期：2026-10-09 · 引擎 `ninfer-serve-120a.exe`（1008 件）+ `bonsai2_27b_ternary_ptq1_native_mtp.ninfer`
> 触发原因：监控页打出 `19:21:45[8095]req#91 ERROR "client disconnected" | openai_chat_completions | think=on | 146 msg`
> 客户端：Hermes 桌面（profile `aiboy`，session `20261007_213933_871896`，provider `custom` → `http://127.0.0.1:8095/v1`，model `qwen3.8-27b-kvmem-64k`）
> 取证：引擎侧 `E:\Bonsai-3\50\request-log.jsonl`（`serve-49040-*` / `serve-104940-*` 两个实例）；客户端侧 `E:\HermesAgent\profiles\aiboy\logs\{agent,errors}.log` + `sessions\request_dump_*_20261009_192534_461801.json`

## 1. 结论摘要（先看这个）

1. **那条 `client disconnected` 不是引擎故障，是客户端的收尾动作。** 引擎把流结束掉（**不带终止 chunk 的 `finish_reason`**）→ Hermes 判流陈旧、**自己把 socket 关掉**（`Shut down the stale stream's socket … (attempt superseded)`）→ 引擎这才记 `request_error: client disconnected`（**实测晚 67 ms**）。同一实例 97 start / 95 done / 1 error，**零 invariant、零 MTP 报错**；1 秒后下一条请求正常完成，那一轮对话**没有丢答案**。
2. **真正的病根在引擎的 `--default-max-tokens`（默认 8192）。** 任何**不带 `max_tokens`** 的请求都被切在 8192；Hermes 的**主对话**和**上下文压缩摘要**都不带 `max_tokens`（引擎日志 `requested_output_tokens_source: server_default`）⇒ 摘要 `finish_reason=length` ⇒ `summary_generation_aborted` ⇒ **压缩永远 commit 不了** ⇒ 上下文只增不减 ⇒ 涨过 `--max_context 65536` ⇒ 之后每轮**干净的 400** `context_length_exceeded`。
3. **已处置**：三个 ④ 启动件加 `--default-max-tokens %DEFAULT_MAX_TOKENS%`（默认 **32768**，`set DEFAULT_MAX_TOKENS=8192` 一词还原），重启后**实测不带 `max_tokens` 的请求吐 23,893 token 且 `finish_reason=stop`**（旧上限下 8192 就断）。
4. 附带三条：①客户端侧「流无 `finish_reason` 收尾」自 10-06 起共 **10 次**（引擎侧待上报，且此时引擎记 `request_error` 而非 `request_done`，**丢掉完成记录**）；②`config.yaml` 默认 model id 与活着的引擎 id 不一致 ⇒ 新会话会 404；③三个 ④ 启动件是 **CR-CRLF（`\r\r\n`）**，其余 8 个 `.bat` 是正常 CRLF。

## 3. 根因：8192 从哪来（实测）

- 引擎自己的契约（`ninfer-serve-120a.exe --help` 原文）：
  `--default-max-tokens N   output limit of a request that sets none (default 8192; 0 generates until the context runs out)`
- 改动前 `grep -l "default-max-tokens" Run\*.bat` ⇒ **0 命中**（三个 ④ 启动件都没传）。
- 引擎请求日志 `request.requested_output_tokens` + `requested_output_tokens_source`：
  - 主对话（146 msg / 25 tools）→ `8192 / server_default`
  - **压缩摘要**（1 msg / 0 tools，`think=off`）→ `8192 / server_default`
- 判断规则（已写进技能与 AGENTS）：`source=server_default` ⇒ 值来自这个 flag；`source=client` ⇒ 客户端自己传的。`finish_reason=length` 归因**先看这个字段**，别先怪池子或模型。
