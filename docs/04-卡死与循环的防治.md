## §0 三十秒版：先做这五件（按顺序，别跳）

| # | 动作 | 为什么先做它 | 验证（能变红） |
|---|---|---|---|
| **F1** | **不回灌上一轮 `reasoning_content`**：服务端**不加** `--preserve-thinking`；客户端 assistant 消息**不带** `reasoning_content` | 这是**实测唯一的退化触发器**（去掉它 = 10 轮 0 次空交付） | 同一剧本 10 轮空交付应为 **0**；**负控**：把它加回去 ⇒ 必须复现退化 |
| **F2** | **加交付护栏**（五态判据 + 点名纠正 + 重试 ≤2） | 唯一能在"模型侧无信号"时拦住的一层 | `undelivered_final = 0`；**负控**：关掉护栏 ⇒ 同配置必须复现（基线约 10~11 次空交付） |
| **F3** | **`max_tokens` ≥ 思考预算 + 交付物** | 思考 token **也占**输出上限 ⇒ 给少了必然"正好截在思考中间 ⇒ 正文 0 字" | 出完整文件时上限给 **16k~20k**；判据 = 产物闭合（有 `</svg>` / 代码围栏成对） |
| **F4** | 给思考通道**补重复惩罚**：`--presence-penalty 1.0`（社区补丁值）或 `1.5`（官方 maintainer 值） | 思考通道官方规格 `presence_penalty = 0.0` ⇒ **完全不抑制重复** | **只能减轻、不能治愈**（实测 12 轮里 7 次退化）；⚠ 别超 1.5（本引擎无惩罚窗口，会伤满屏重复标签的 HTML/SVG） |
| **F5** | 要稳就**降 effort / 关思考**（`--default-reasoning-effort none`） | 实测 12 轮 0 退化、复用稳定 99.0~99.9% | 但**病 B（同一自选计划重复）仍在**（9/11 轮）⇒ 关思考不等于全好 |

**取舍一句话**：`F1`（安全）与"复用不重填"目前**对立**（不回灌时 `cache` 掉到 81.6~89.8%、TTFT 10.4~14.5 s）；`F3` 决定**交付完整性**；`F2` 是唯一兜底；`F4/F5` 是强度调节。**理想组合 = F1 + F2 + F3。**

## §1 症状全谱（**对照定位，然后只改那一行的"先做什么"**）

| # | 症状 | 机器可判的判据 | 来源 | 真因（当前最好解释） | **先做什么** |
|---|---|---|---|---|---|
| 1 | **空交付** `EMPTY` | 正文 **< 400** 字符；或"该给整份文件"的轮次里检出量 **< 2000** 字符 | `实``测` | 回灌推理 + 长思考 + `max_tokens` 不足 | F1 + F3，F2 兜底 |
| 2 | **半截** `TRUNCATED` | 代码围栏未闭合（三反引号计数为奇数）；或有 `<svg>` 无 `</svg>`；或 `finish_reason=length` | `实``测` | `max_tokens` 被思考吃光（**"有文件" ≠ "文件能用"**） | F3（上限提到 16k~20k） |
| 3 | **固定点** `FIXED_POINT` | 与上一轮答案**规范化空白后逐字相同** | `实``测` | 回灌 + 思考档无重复惩罚 | F1 + F4；平台判失败重发 |
| 4 | **自选计划重复** `SAME_PLAN` | 抽"计划行"（`OPT:`/`NEXT:`/`下一步：`）归一化后与上轮相同 | `实``测` | **任务侧**：环境从不纠正、模型确实没有新点子（**关思考也发生**） | 给循环**加新鲜约束**，或判该态为失败 |
| 5 | ★ **宣布了不干活** `PLAN_ONLY` | 连续多轮答案只有一行计划（实测 **61 字符**：`OPT: …` + `STATUS: WIP`），**8 轮逐字相同**；此时它**仍答得对**项目编号 ⇒ **不是忘了，是不干** | `实` | 思考开 + 预算每轮打满 + `--preserve-thinking` 把它自己的计划留在上下文里 ⇒ 计划成固定点 | F1 为主；F2 判 `EMPTY`/`SAME_PLAN` |
| 6 | ★ **纯工具轮空壳** `SHELL_LOOP` | **连续多轮 assistant 只发 `toolCall`、`text` 为空**（实测 **5 轮**只调 `conversation_read`），工具结果把上下文撑爆后被中断 | `测` **测试用户** | 工具轮上下文增长快 + 池太小 ⇒ **中段静默丢失** ⇒ 模型"看不到"自己刚拿到的结果，只好再调一次 | ① 判"纯 toolCall 无 text"为失败、要求重发；② **限同一工具连调次数**；③ `--kv-capacity` **≥ 题面 token 数** |
| 7 | ★ **词表递归** `VOCAB_RECURSE` | 思考滑向**同义词罗列**（实测原文：*"…quality excellence superiority… pertinent applicable pertinent…"*），**自我指令"停下给最终答案"失效**，正文永远出不来（`never outputting </think>`） | `测` **测试用户**｜`社` Qwen issue #88 | 思考档 `presence_penalty = 0.0`（官方规格）+ 本引擎**无惩罚窗口** | F4（别超 1.5）+ F3；**要限思考用 `--default-thinking-budget`，别用 `max_tokens` 硬截** |
| 8 | **思考撞上限** `OVER_BUDGET` | `thinking N/N` **每轮打满**；`finish_reason=length` | `实` | 预算给得比模型自然思考量小 ⇒ **一直在削它** | 给足或干脆不设（见 §5）；**别用截断限思考** |
| 9 | **平台守卫掐断** `PLATFORM_GUARD` | 思考中途被截断、**不报任何错**；平台有 guard/notice/abort 事件；守卫 `trips` 计数增长 | `实`（DSH 旋钮读数）｜需求方提交 | 守卫**只看统计量**（短语重复次数、关键字符数量）⇒ **思考越长越容易越线** | 放宽 `threshold`（必要时抬 `minChars`/放大 `window`）；确认 `action` 是"提示"而非"中断"（**详见 §4**） |
| 10 | **客户端中止** `CLIENT_ABORT` | `HTTP 499` + `client disconnected`；**引擎未崩、非 OOM** | `测` 测试用户（Chatbox 弹窗）· 测试用户（pi 平台看门狗，1,903 条消息会话） | **客户端侧**（弹窗确认框 / 平台看门狗 / 自家读超时） | 关掉"自动执行/确认框"；把长空档（prefill、工具解析）纳入客户端超时预算 |

| 12 | **工具名大小写漂移** | `conversation_read` → `Conversation_read`；引擎 request-log 字段 `invalid_tool_name` / `undeclared_tool` | `测` 测试用户 | 采样/惩罚设置 + 模型侧不稳 | 用 request-log 的 `tool_call_parse` 定位；关思考后大幅减少 |
| 13 | **工具集与系统提示不一致** | 代理剥掉了请求里的 `tools`，但系统提示仍宣称"你有这些 skill" | `测` 测试（我方推断，**未验**） | 模型反复尝试调用不存在的工具 | **要剥就一起剥**；判据 = 同 prompt「带 tools vs 剥 tools」两臂对照 |

## §3 三层处方（L1 参数 / L2 采样 / L3 平台）

### L1 参数层（引擎侧，零依赖）

| 项 | 怎么设 | 理由 |
|---|---|---|
| **默认不思考** | `--default-reasoning-effort none` | 实测不思考臂 **0 次空交付**；客户端仍可按请求选 `low/medium/xhigh` 打开思考 |
| **绝不回灌上一轮推理** | 关 `--preserve-thinking`；客户端**不回传** `reasoning_content` | 见 §2，主因 |
| **输出预算给足** | `--default-max-tokens` 与客户端 `max_tokens` **≥ 思考量 + 交付物** | `max_tokens` 是**硬截断**：给少了会**正好截在思考中间 ⇒ 正文 0 字**（实测 `64` ⇒ 思考 64、正文 0；`≥512` 起正常） |
| **要限思考就别用"截断"限** | 用 `--default-thinking-budget N`（命中时引擎插入提示 + 补规范 `</think>`） | 前者是"体面收束"，后者是"掐在半路" |
| **工具调用场景 `presence=0`** | `--presence-penalty 0` | 高 presence 会跟工具调用的**结构化 XML** 打架：`temp1.0+pres1.5` ⇒ 工具块泄漏成正文（模型改用自造标签）；`temp0.7+pres0` ⇒ 连续 4 次正常 |
| ★ **`max_tokens` ≤ 池 token 数** | 客户端约束（**`docs\00`/`docs\12` 都没写这条**） | 测试（全 503 那例）：`max_tokens=32,000` ⇒ **worker 崩且不自愈**；同一机器 `64` 就能活 |

### L2 采样层（按"这一轮是否思考"配对两套预设）

| 通道 | temperature | top_p | top_k | min_p | presence |
|---|---|---|---|---|---|
| 思考中（thinking） | 1.0 | 0.95 | 20 | 0 | **0.0（官方规格，问题所在）** |
| 思考结束后产出（post-thinking，须 `--post-thinking`） | 0.2 | — | — | — | 0.0 |
| 不思考（非思考通道） | 0.7 | 0.80 | 20 | 0 | 1.5 |

- 官方 maintainer 配方（思考档）：`temp 1.0 + top_p 0.95 + top_k 20 + min_p 0 + presence 1.5` ⇒ 实测 **12 轮 1 次空答案**（比基线好），但**不归零**。
- ⚠️ **"催快"的自伤**：某些实现把"简短"当档位插进 system（我们的 `reasoning_effort=low` 就是插一句话，**不是 token 预算**）—— 实测那档**更慢、更费 token、且答错更多**（跳过验证抢答，抢答失败又在本轮反复修补）。**要快就用"不思考"，不要"催它简约"。**

### L3 平台层护栏（**唯一能在模型侧无信号时拦住的一层**）

**判据五态**（机器可判、阈值显式）：

| 状态 | 判据 | 建议阈值 |
|---|---|---|
| `EMPTY` | 交付物缺失 | 正文 < **400** 字符；或"要求给完整文件"的轮次里检出量 < **2000** 字符 |
| `TRUNCATED` | 半截 | 代码围栏未闭合（计数为奇数）；或 `<svg>` 无 `</svg>`；或 `finish_reason=length` |
| `FIXED_POINT` | 与上一轮**逐字相同** | 规范化空白后字符串相等 |
| `SAME_PLAN` | 自选计划重复 | 抽出计划行（`OPT:`/`NEXT:`/`下一步：`）归一化后相等 |
| ★ `SHELL_LOOP` | **纯工具轮空壳**（**2026-10-01 补**，见 §1 第 6 条） | assistant 消息**只有 `toolCall`、`text` 为空**，且**同一工具连续出现 ≥3 次** |

**动作**：判定失败 ⇒ **带上纠正指令重发**（同一引擎、同一会话，把被拒的回答 + 纠正一起送回去），上限 2 次；仍失败 ⇒ **中止或降级，不许当成功继续往下跑**。
参考纠正文案（实测有效）：

> 【交付检查未通过 · 第 N 次重试】<点名这次是哪一条：没有交付物 / 只给了计划 / 文件写到一半缺结束标签 / 与上一轮逐字相同 / 只调工具没给正文>。
> 现在只做一件事：立刻输出**完整且闭合**的产物；空间不够就**先精简但必须闭合**；
> 不许只写计划、不许写「同上」、不许重复上一轮的措辞。若上一轮的方案已完成，就换一个**不同**的点。

**实测效果**：把护栏加到**最差配置**上（思考开 + 回灌 + 预算打满，该配置基线约 **10~11 次空交付**）⇒ 10 轮里护栏触发 1 次（第 8 轮 `EMPTY` → 重试 → 正常），**`undelivered_final = 0`**，完整率 **78%**，引擎 **0 投诉**。

#### 接收方要实现什么（照这个表填）

| 要素 | 你要做的事 | 判据（能变红） |
|---|---|---|
| 判定点 | 在**你的**请求/响应链上拿完整响应文本再判（不要在流中途判） | 把阈值调到不可能满足（如 10⁹）⇒ 每一轮都必须判 `EMPTY` |
| 上一轮答案 | 判 `FIXED_POINT`/`SAME_PLAN` 需要"上一轮答案"与"上一轮计划" | 故意重发同一条 ⇒ 必须判 `FIXED_POINT` |
| 重发通道 | 必须在**同一次调用内**能带新消息重发（很多平台的"重试"只是原样重发，那没用） | 重发请求里能看到纠正指令（消息数 +2） |
| 计数记账 | `guard_fired` / `rescued_by_retry` / `undelivered_final` 三个计数 + 每轮 JSONL | `undelivered_final` 必须能非 0（否则计数是假的） |
| 关闸开关 | 一个 `off` 开关（出问题时能摘掉护栏） | 关掉后行为逐字回到未加护栏 |

> 我们本机有一个参考实现（Python，约 200 行，**代码不随本页发**）：代理把上游流式响应**边转发边累积**，判不过就**在同一条响应里**追加标记 + 用纠正指令重发的答案。

## §4 平台守卫层：**"思考被莫名截断、还不报错"**（2026-10-01 需求方提交）

**机制**：这类守卫**不看你是否在思考**，只看**统计量** —— 某个短语在窗口内的**重复次数**、一段文本里的**关键字符数量**。
⇒ **思考越长，这些统计量越容易越线** ⇒ 守卫判定"卡死了" ⇒ **掐断**（有些平台**不报错**）。

**DSH 实测旋钮（本机 `loop_guard_status`，2026-10-01）** —— "宽容度"具体就落在这些参数上：

| 旋钮 | 本机当前值 | 含义 / 往哪边调更宽容 |
|---|---|---|
| `channels` | `reasoning` + `text` | **连思考通道一起统计** ⇒ 长思考天然更容易触发 |
| `threshold` | **12** | 同一短语在窗口内重复多少次算"卡死" ⇒ **抬高 = 更宽容** |
| `window` | 48 | 统计窗口 ⇒ 放大 = 更宽容 |
| `maxPhraseChars` | 8 | 多长的片段算"一个短语" |
| `minChars` | **400** | 累计字符数不到这个数**根本不判**（保护短回答）⇒ **抬高 = 更宽容** |
| `cooldownMs` | 20000 | 两次判定之间的冷却 |
| `action` | **`notice`** | ★ **本机是"只提示"，不是"掐断"** |
| `guardSubagents` | true | 子代理也受同一套管 |
| `trips` | **0**（3 个会话） | 本机至今**一次都没触发过** |

**处方（按顺序试）**：① 抬高 `threshold`（必要时同时抬 `minChars` / 放大 `window`）；② 确认 `action` 是"提示"而不是"中断"；③ 若平台另提示"**思考达到上限**" ⇒ **把思考上限（reasoning 预算）拉高**，别用调小 `max_tokens` 去截。

**⚠ 诚实边界**：本机 `action=notice`、`trips=0` ⇒ **我们手上没有"DSH 掐过"的读数**。真发生"掐断且不报错"，要么该平台的 `action` 被配成了中断，要么是**另一个平台/另一套守卫**。

**判据（把"守卫掐的"和"别的原因"分开）**：
1. 平台侧有没有 guard / notice / abort 事件记录？**有 ⇒ 基本就是它**（抬高阈值后重跑同一题面，事件应消失）。
2. 把**同一题面的思考量压短**（`reasoning_effort low` 或缩短题面）⇒ 不再截断则支持"守卫越线"这一支。
3. 看守卫 `trips` 计数**是否增长**：增长 = 真触发；不增长 = 不是它。
4. 同时看引擎侧 `finish_reason`：**`length` = 硬截断（预算问题）**；**`stop` 却内容半截 = 更可疑（平台侧）**。

## §5 思考过长怎么处置（**别一刀砍**）

> **判断 H1**：思考长度与能力相关 —— 压低思考预算会明显降智（**我方判断，未做对照实验**）。

**支持证据（我方四臂，全部可复算）**：
1. **预算在每一场里都是"紧的"**：给 1,500 ⇒ **每轮用满 1,500**；给 8,192 ⇒ **每轮用满 8,192**。⇒ **模型每次都想用更多，我们一直在削它。**
2. **削思考的两个可测代价**：① **半截**（思考 token 也占 `max_tokens`，A7：**12/12 产物写不完**）；② **推理被生硬切断**（引擎在预算处注入控制符并补 `</think>`，既伤复用，也让"计划"停在半句上）。
3. **反向对照**：思考关（A1）虽 0 次空交付，但**病 B 最重**（同一自选计划重复 **9/11 轮**），且完全没有推理能力 ⇒ 与"砍思考 = 降智"一致。

**★ 好消息：放开思考与防自旋并不冲突。** A2 每轮**照样把预算打满**（`thinking 1,500/1,500, control 25`），却 **0 次空交付**（10 轮，答案 15k~24k 字符）⇒ **防自旋靠的是"不回灌"，不是"压思考上限"。**

**放开思考必须配套的四件事**：

| # | 配套 | 反例（不做的后果） |
|---|---|---|
| 1 | **`max_tokens` ≥ 思考 + 交付物**（想超长思考又要完整文件 ⇒ 给到 **32k 级**） | A7 思考 8,192 + 上限 12,000 ⇒ **12/12 半截** |
| 2 | **别用"每轮必满"的小预算**：给足让它自然 `</think>` 收尾，或不设 | 1,500 每轮用满 ⇒ 推理每轮被切一刀 |
| 3 | **护栏兜底**（§3 L3） | A7 放开后**仍有 1/12 空交付**（`finish=stop`、预算未满 4,514/8,192、答案 0 字符） |
| 4 | **认代价**：超长思考 ⇒ 单轮慢（思考段 decode **70~130 tok/s** vs 答案段 **300~520**）、上下文消耗大 | 读数见各臂 `engine.err.log` |

**待测实验**（**把 H1 从经验变成读数**）：同一剧本、`max_tokens` 给足 **40k**，只改思考预算跑三档 ① 1,500（削）② 8,192 ③ 不设上限（自然收尾）；每档都算：结构约定保留数 · 自选计划新鲜度 · 自修质量 · 产物完整率 · 空交付轮数 · 单轮耗时。

## §5.5 ★ 另一条路：换「简思考」的微调模型（**推荐我们的 Swift 档**）

> §5 是「**顺着它**」（给足预算 + 不回灌 + 护栏兜底）；本节是「**让它少想**」—— **换一档天生思考更短的微调权重**。

**推荐**：当"超长思考"已经实际拖慢你的流程时，**优先试我们的 Swift 档**（Swift 微调系列 —— 把修正直接合进权重的那一版）。上游自己给过一张「**思考 token 中位数降幅**」表：**它就是想得少的那一档**。

**代价（我方实测，必须和推荐一起看）**：同一引擎、同一口径的 20 题门，**基础档 19/20 → Swift 16/20**，其中 3 道是**确定性答错**（四条路径全复现、6 次独立运行、逐题逐位可复现 ⇒ **不是抽样噪声**）；PPL 基本持平 ⇒ **它动的是"推理行为"，不是"会不会说话"**。

**所以按场景选，别一刀切**：
- **推理题 / 多步 agent（正确率优先）** ⇒ **别切**；
- **长思考把流程拖死、任务容错高（创作 / 改写 / 单步工具 / 长文档流转）** ⇒ **值得试**。

**已知坑**：Swift 那一档**不能配"行粒度"KV** —— 用 `fp8` / `rk8v4` / `int8` 时它会**只吐 2 个 token 就结束，而引擎不报错**（复现 5/5）⇒ 用 **`k8v4`（或 `bf16`）**。

**怎么自己定**（别照用我们的题）：同一剧本跑两臂，**只换权重这一个变量**，三个数一起看 —— ① 你的题门答对率 ② 思考 token 中位数 ③ 护栏触发次数。**掉幅可接受、后两项明显下降 ⇒ 就切。**

## §9 agent 执行清单（**照这个做，别发明新判据**）

  {turn, text_chars, has_file, file_closed, thinking_tokens, thinking_budget,

**判据**：如果五态全 0 且 `undelivered_final = 0` ⇒ **你这个环境没有这个病，别改任何东西。**

**第二步 —— 按 §1 表定位到具体一条，然后只改那一行对应的"先做什么"。**

**第三步 —— 每次只改一件事，并用"负控"确认**：

| 你改的 | 正向判据 | 负控（必须能变红） |
|---|---|---|

| 加护栏（F2） | `undelivered_final = 0` | 关掉护栏 ⇒ 必须复现（基线约 10~11 次） |
| 抬 `max_tokens`（F3） | 产物闭合率上升 | 上限调回 12,000（预算 8,192）⇒ 应回到 12/12 半截 |
| 抬平台守卫阈值（§4） | 截断事件消失 | 阈值调回 12 ⇒ 同一题面应再次截断 |
| 抬思考预算（§5） | 质量上升**且空交付不上升** | 若空交付随思考长度上升 ⇒ **F1 没做到位**，先回去做 F1 |

## §10 边界与未验（**别把本页当万能**）

1. **护栏不是"修好模型"**：它只让"空/半截/重复/纯工具轮"**不交付出去**（保住质量下限），根因仍在"回灌 + 长思考"这条组合上。
2. **思考档的收益本身未量**：我们没做"同任务、思考开/关"的配对评测（谁更聪明、值不值那个延迟）⇒ **标未验**。
3. **`--default-thinking-budget` 的副作用**：命中预算时引擎插入提示并补 `</think>`（实测那一段控制符约 **25 token**），期间**控制符也计入输出上限**；预算设太大会失效、太小会让它"想不完"。
