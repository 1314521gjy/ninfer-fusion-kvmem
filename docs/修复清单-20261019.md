## 1. 已修（6 项，均有 A/B 证据）

### 1.1 「池 < 上下文」启动即报错
- **现象**：`--kv-capacity` 小于 `--max-context` 时，prefill 单步需求超过可用页数，直接 429（`this step needs 20 free, 8 available`）。
- **根因**：单步 prefill 没有按可用页数夹紧，按完整上下文一次性申请。
- **修法**：`NINFER_PREFILL_CHUNK_AUTO`（默认 ON），运行期把单步 prefill 夹到 `(usable − slack) × 64`（slack = 8 页）；`src/models/qwen3_5/program/planning/startup.cpp`。
- **判据**：负控 `AUTO=0` ⇒ 复现 429；正控 ⇒ 200 + `prefill_chunk auto-clamp: requested/effective/usable_pages/slack`。

### 1.2 `429 context cache exhausted: an idle Engine found no placement`
- **根因**：`ModelContract::CapturePressurePlanningSession` 别名缺失 ⇒ 契约不满足 ⇒ 选择器退化为 `NoPressurePlanner`（从不施加压力规划）。`src/runtime/engine/context_cache/resource_manager.h:199-211,104-197`。
- **修法**：`src/models/qwen3_5/program/runtime_types.h` 增加一行别名，启用 `MaterializationPlanner`。
- **判据**：4/4 请求 200；日志出现 `[diag] mp-planner-enter-body cand=2 → plan-ok`。

### 1.3 自动选档（L0）漏算宿主需求 / 选错档
- **根因**：候选档位只按显存算，没有逐档校验宿主页需求 `host_pages ≥ logical_pages − pool_pages`。
- **修法**：`startup.cpp` 改逐档 feasible（含 `host_needed ≤ host_avail` 与预留），不满足则硬抛而不是静默降级。
- **判据**：`chosen=rk2v4-e8 reason=ring-feasible`；否证：伪造宿主不足 ⇒ 启动即拒。

### 1.4 分片网关把结构单元劈开
- **现象**：94K 材料按 `\n\n` 切分（材料只有单换行）⇒ 切出碎片，7 片全 `NOT_PRESENT`，聚合结果错。
- **修法**：`agg_gateway.py` 改整单元（空行分段）打包 + `--max-shard-tokens` + `unit_broken` 拒答（`sum_method="unit_broken"`、`low_confidence=true`），不再回落模型 reduce。
- **判据**：`partition_exact=True`、`n=3`、`final=3241`（真值 3,241，逐片 1080/1081/1080 全等）；负控：单单元 > 池 ⇒ 必拒答。

### 1.5 250K 题面 + MTP 撞 429
- **根因**：宿主页不足（`--host-kv-mib 3264` 只剩 28 页），不是显存不足。
- **修法**：`--host-kv-mib 4096`。
- **判据**：250K ⇒ 200 且答对；`cannot_free=0`。

### 1.6 投机开关不可见
- **现象**：无法从日志判断投机是否真的开启。
- **修法**：启动打 `[spec] backend=… draft_tokens=… adaptive=… attention_window=… ngram=…`，关闭时也打 `backend=none`（`apps/serve/main.cpp`、`apps/cli/main.cpp`）。
- **判据**：`findstr "[spec] backend="` 命中；本机实测 `backend=mtp draft_tokens=1 adaptive=0 attention_window=8 ngram=15`。

## 3. 定性为引擎级限制（2 项，非本线可修）

### 3.1 极小池 + 长输出 ⇒ 静默错内容
- **现象**：池 1,536（24 页）+ 输出 512 ⇒ HTTP 200、无告警，但内容缺号 203（自 127 起）、回卷 4 次、重号；对照池 1,792（28 页）⇒ 1→280 连续无缺。
- **可用约束**：长输出需 `max_tokens ≤ free × 64`（**该约束尚未实现**）。
- **候选机理**：驱逐无写屏障（`context.cpp:2425`、`kv_store.h:553-570`），根因未定位。

### 3.2 题面 token > 池 token ⇒ 中段丢失
- **出处**：引擎自带警告 `src/serve/generation_service.cpp:299-337`；注释自述"the MIDDLE … measured to go missing with no error line, HTTP 200 and a plausible wrong answer; the root cause is not localized. Treat every answer to this request as unverified"。
- **我们这条线（ring + host 两层 + 证据取回）解决不了**：中段页多为 partial-commit / writer 未清，按 coverage 账本（`context.cpp:1900-1912`）不可降级 ⇒ 中段不可能全驻留。
- **对外约束**：`题面 token > 池 token ⇒ 单请求答案不可信`；**"没看到警告"不等于安全**（`:335-337`）；超池必须走分片网关，每片 ≤ 池。

## 4. 配置级修复（2 项）

1. **`--max-shared-prefixes 0` 必带**：ring 模式（池 < 逻辑页）下，共享前缀快照会触发 `active KV snapshot page ownership is not ordered`（`kv_store.h:1544`）/ `full page is not stable`（`:1540`）。默认值是 `max(max-concurrency, 7)`，会导致上述 fast-fail 断言。
2. **240K+ 宿主页**：见 1.5。

## 5. 三 arch 引擎构建（2026-10-19，本机实测）

| arch | 覆盖 | 字节 | 构建耗时 | gencode 自证 |
|---|---|---:|---:|---|
| sm86 | RTX 30 系 | 820,153,856 | 34.6 min | 388 × `compute_86`（负控：无 89/120a） |
| sm89 | RTX 40 系 | 801,324,544 | —（既有） | 389 × `compute_89` |
| sm120a | RTX 50 系 + RTX PRO 6000 Blackwell | 710,338,048 | 23.5 min | 415 × `compute_120a`（负控：无 86/89） |

构建要点（踩坑留碑）：
- **`sccache` 不能作为 `CMAKE_CUDA_COMPILER_LAUNCHER`**：会得到 `fatbinary fatal : Could not open input file '<tu>.ptx'`（中间 `.ptx` 在沙箱里找不到）。CUDA 编译留空；C/CXX 可继续用。
- `--split-compile=4` 显著缩短单线程 `ptxas` 长尾（sm86：122.8 → 34.6 分钟）。
- sm120a 必须 CUDA ≥ 13.1（CUDA 12.8/12.9 会错误编译 sm_120a kernel），`CMakeLists.txt` 已加硬守卫。
- 单文件多 arch 不可行：三份合计 2.17 GiB，超 PE 镜像 2 GiB 上限（`LNK1248`）。
