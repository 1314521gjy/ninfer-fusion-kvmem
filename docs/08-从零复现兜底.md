### 1.1 运行前提（`README.md` §1 的口径）

| 项 | 要求 | 依据（实测） |
|---|---|---|
| GPU | **RTX 40 系（sm_89）** —— 本包**只含 sm_89 引擎**，其它架构被启动件**直接拒绝** | `start-8090.bat` 的 arch 检查 |
| 显存 | 权重 7.28 GiB + 运行时 **1.54 GiB** ⇒ **建议 ≥12 GB**（本机 32 GB 卡启动后 `free 22.5 GiB`） | `loading weights \| 7.28 GiB`、`capacity \| … runtime 1.54 GiB` |

## §2 最短路径：跑到服务

```
1) 双击  start-8090.bat
2) 等日志出现：listening on http://127.0.0.1:8090 | model qwen3.8-27b
3) 就绪探测：
   curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:8090/v1/models      → 期望 200
```

启动器实际交给引擎的命令行（**照抄 `start-8090.bat` 第 85–91 行**，你就是想手敲也用同一份）：

```
ninfer-serve.exe "<pkg>\model\Ternary-Bonsai-2-27B-ninfer-v3.ninfer" ^
  --host 127.0.0.1 --port 8090 --model-id qwen3.8-27b ^
  --max-context 65536 --kv-capacity auto --kv-dtype k8v4 ^
  --host-kv-mib 4096 ^
  --max-concurrency 1 --no-thinking --greedy ^
  --max-private-continuations 2 --max-shared-prefixes 4 --max-long-anchors-per-continuation 2 ^
  --spec mtp --draft-tokens 2 --lm-head-draft
```

**自动化/脚本里调用时**：先 `set NINFER_AGENT=1`，否则启动器在退出前会 `pause` 等人按键
（出处：`start-8090.bat` 第 41/47/95 行的 `if not defined NINFER_AGENT pause`；我们自己的自检脚本就是这么做的，
见 `01-部署与编译总白皮书.md` §9 索引里的 `selftest-8090.ps1:38`）。

## §3 用**包自己的入口**自证：复用到底通没通

> **纪律**：手敲命令起服务**不算**自证。要证明的是"**这个包、用它自己的入口、能跑出它承诺的读数**"。

### 3.1 期望的启动日志（逐字，取自 2026-09-30 实测臂）

```
INFO  engine | device profile nvidia-geforce-rtx-4080-super-sm89: 49 routed keys (...)
INFO  loading weights | 7.28 GiB
[ninfer] reuse host-backed: on                    <- 复用门控确实打开（没这行 = 没生效）
INFO  capacity | KV 9,728 tokens, k8v4, auto | pages 152/152 | runtime 1.46 GiB | free 22.5 GiB
（本档默认 KV 档自 2026-09-30 起为 **k8v4**；fp8 时代的同一行是 `…, fp8, auto | … runtime 1.54 GiB`，仅作历史。）
INFO  context cache | 1 active + 1 cached device states | host 8 states, 4.00 GiB KV | private 2 | shared 4 | anchors 2
INFO  listening on http://127.0.0.1:8090 | model qwen3.8-27b | auth disabled
```

（**照抄自 `判据.txt` §2 —— 口径与后续更新以后者为准**。）

### 3.2 第二轮自证（**这是本包的全部意义**）

| 轮次 | 读数（形状） |
|---|---|
| 第 1 轮（约 40k token 提示，冷） | `prompt 40,056 / cache 0 (0.0%) / TTFT 19.7s / total 19.9s / prefill 2.05k tok/s` |
| 第 2 轮（**同会话追问**） | **`prompt 40,097 / cache 40,068 (99.9%, private endpoint) / TTFT 154 ms / total 235 ms / decode 148.1 tok/s`** |
| 答案 | 长提示中段的针，**逐字**答对（实测标记 `NINFER-NEEDLE-7731`） |
| 引擎自证行 | `[ninfer] adopt host-backed: frontier=40068 need=627 usable=152 host_backed=484` |

⇒ **第二轮 19.9 秒 → 0.235 秒（≈85×）**，而设备池只有 **152 页**（≈1.54 GiB 运行时）。
`need=627 usable=152` 就是"前缀 627 页、池只有 152 页"，而它**照常复用**。

（出处：包 `README.md` §4 与 `判据.txt` §3 —— **这两份是权威口径，本文这张表只是转述**。完整验收判据表与"每条怎么变红"见 `01-部署与编译总白皮书.md` §7。）

> **口径小差留着不掩盖**：`判据.txt` §1 记"自启动到可服务约 5 秒"，`README.md` §3 记"约 1 秒 + 权重加载 3–4 秒"——
> 两处原文都保留，属同一量级的不同记法。

## §4 起不来时：**按这个顺序查**（症状→处方的逐条表不在本文，见 §4.2）

### 4.1 决策树（从上往下，第一步红就先解决它）

```
① 窗口一闪就没 / 打印 [ERROR] 关于 compute capability
     ⇒ 架构不符或读不到 cc。本包只发 sm_89（RTX 40 系）。
       退出码 5 = 卡不是 8.9；退出码 6 = nvidia-smi 读不到 cc。
       （出处：start-8090.bat 第 35–49 行；可用 NINFER_AGENT_CC 覆盖读数，仅用于测试。）

② 退出码 0xC0000135（缺 DLL）
     ⇒ 先确认 engine\ 下 9 个 DLL 都在；再设 CUDA_BIN 指向 CUDA 的 bin 或 bin\x64。
       （启动器已内置探测：CUDA_BIN → %ProgramFiles%\…\CUDA\v13*\bin → v12*\bin → 包内 engine\；
        出处：start-8090.bat 第 20–30 行。）

③ 启动期 FATAL（有明确文字）
     ⇒ 引擎是"拒绝启动 + 打印确切数字"，不是"莫名崩"。见 §4.2 的表。
       两条最常见的：主机层装不下（抬 --host-kv-mib）、--max-concurrency 不是 1（本档只能单路）。

④ 端口 8090 被占
     ⇒ 包内门会先告诉你：自检-包完整性.ps1 的 PKGCHECK_PORT 项在端口被占时变红。
       查占用：Get-NetTCPConnection -LocalPort 8090 -State Listen

⑤ 服务起来了但**答案是错的 / 第二轮没复用**
     ⇒ 九成是**五个开关缺一**（最危险的是缺 NINFER_KV_RETRIEVE：档照样起、复用照样 99.9%、中段答案错、
       **一行错误日志都没有**）。参见 §4.3 的自检顺序与 01 白皮书 §6。
```

### 4.2 症状 → 处方（**指针，不复制**）

| 症状（原文片段） | 去哪看 |
|---|---|
| `NINFER_KV_WINDOW (KVMem ring) needs a Host KV tier that can hold every page the Device pool cannot: host_pages=… pool_pages=… logical_pages=…` | `判据.txt` §4 第 1 条（含公式）；`01` 白皮书 §7 判据 G |
| `NINFER_KV_WINDOW (KVMem ring) requires --max-concurrency 1` | `判据.txt` §4 第 2 条 |
| `ERROR worker crash: Paged KV reservation invariant was violated` | `判据.txt` §4 第 3 条（本档设计上不该出现 ⇒ 请把整份日志发回，并注明 host-kv-mib / max-context / kv-capacity 三个值） |
| 进程起不来、退出码 `0xC0000135` | `判据.txt` §4 第 4 条 |
| `unknown argument: --disk-cache` | `判据.txt` §4 第 5 条（本档引擎**没有**磁盘缓存参数，**不要加**） |
| 其余症状 | `02-排错手册 · 预案与处方.md`（含两个"**静默变差**"陷阱：不报错但答案会错） |

### 4.3 五开关自检（**按这个顺序，别跳**）

1. 日志里有没有 **`[ninfer] reuse host-backed: on`**？没有 ⇒ 门控没生效，回去看启动器有没有被人改过。
2. 有没有 **`adopt host-backed: frontier=… need=… usable=… host_backed=…`**？没有 ⇒ 没有任何请求被采纳复用。
3. **两轮针测**：把唯一标记放在**长提示中段**，第二轮追问，**必须逐字答对**。
   ⚠️ 判据要认对：门控关掉时第二轮**仍是 200**、短提示下答案**也可能仍然对**，
   **红的是 `cache%` 与 `adopt` 计数**，不是 HTTP 状态码（坑表 §5.141）。
4. `publish host-backed:` 是**无条件**行为，**别拿它当门控开关的判据**（`判据.txt` §5）。

## §5 包内四个自检脚本（**先跑它们，再怀疑别的东西**）

| 脚本 | 怎么用 | 期望读数（判据） | 怎么变红 |
|---|---|---|---|
| `自检-包完整性.ps1` | `powershell -NoProfile -ExecutionPolicy Bypass -File .\自检-包完整性.ps1` | `PKGCHECK_VERDICT=PASS`、`PKGCHECK_FAILED=0`（17 项判据）；关键项含 `entries=35 untracked=0 bad=0` | 改一个字节 / 新增未入册文件 / 脚本含非 ASCII / 端口被占 / 少一个 DLL —— 各自红了对应那一项（该门自带 **9 条负控**） |
| `update-sha256sums.ps1 -Check` | 同目录下 `-Check` | `rc=0`、`changed=0 missing=0` | 任何文件被改动 |
| `自检-引擎与卡匹配.ps1` | 直接跑 | 打印 cc / 卡名 / 显存并给 PASS | `-ForcedCc 12.0` ⇒ `FAIL`、exit 1 |
| `档位探针.ps1` | `-Log <引擎 stderr 日志>` | `PROBE_*` 行 + `PROBE_VERDICT=PASS`；**引擎没打印的字段打 `UNKNOWN`**（如实暴露缺口，例如 `PROBE_KV_BYTES_PER_TOKEN=UNKNOWN`） | 喂被截断的日志 ⇒ `PROBE_MISSING=n` ⇒ `FAIL` |

> ⚠️ 跑这些脚本用 `powershell -File`（本机 `pwsh` 工具实为 **Windows PowerShell 5.1**：无 BOM 的非 ASCII `.ps1` 会被按 ANSI 读，
> 见坑表 §5.149）。**别把会写状态的脚本管道给 `Select-Object -First N`**（会掐断子进程导致写入静默不发生，坑表 §5.148）。

2. **单路**：`--max-concurrency > 1` 被硬拒。

4. **逐页可见性 trace 未做**：复用正确性由两轮针测间接证明。
5. **磁盘层零实测**；**>262144 未验**且已裁决不做。
6. **本文所有读数都来自** 2026-09-30 在本机（RTX 4080 SUPER / 32 GB）上、**通过本包自己的入口**跑的实测；
   换机器换驱动后**请重跑 §3 的两轮自证**，不要照抄本文数字当自己的结论。
