## §1 逐条可抄项

### P-01 · C2326：lambda 内用被捕获的 `constexpr auto kernel` 函数指针（**4 个文件，5 处**）

- **病根**：`constexpr auto kernel = <name>_kernel<…>;` 之后，在嵌套 lambda 里 **捕获** `kernel`（`[&]`）用于 `kernel<<<…>>>` 或 `cudaFuncSetAttribute(kernel, …)` ⇒ MSVC 报 C2326。
- **修法（机械、编译期等价）**：**在 lambda 内写完整模板实例**，不再捕获那个变量。

| 移植到（我们的文件） | 位置 | before → after |
|---|---|---|
| `src/ops/linear/bf16/bf16_template_launch.cuh` | `launch_bf16_a16_gemv`（~`:31`） | `cudaFuncSetAttribute(kernel, …)` → `cudaFuncSetAttribute(bf16_a16_gemv_kernel<Schedule, Output, Epilogue>, …)` |
| 同上 | `launch_bf16_a16_sliced_k_mma`（~`:109`） | `kernel<<<grid, …>>>` → `bf16_a16_sliced_k_mma_kernel<Schedule, Output, Epilogue><<<grid, …>>>` |
| `src/ops/linear/fp8/fp8_template_launch.cuh` | `launch_fp8_a16_sliced_k_mma`（~`:80`） | → `fp8_a16_sliced_k_mma_kernel<Schedule, Output, Epilogue, Rows><<<…>>>` |
| `src/ops/linear/nvfp4/nvfp4_template_launch.cuh` | `launch_nvfp4_a16_sliced_k_mma`（~`:86`） | → `nvfp4_a16_sliced_k_mma_kernel<Schedule, Output, Epilogue, Rows><<<…>>>` |
| `src/ops/linear/nvfp4/nvfp4_a4_tma.cuh` | `launch_nvfp4_a4_tma_mma`（~`:441`，**两个 `#ifdef` 分支都要**） | → `nvfp4_a4_tma_kernel<Schedule, Epilogue, Output, Rows><<<…>>>` |

- **判据**：**绿** = 同一份源码在 MSVC（尤其 19.44）下编过，且 **PTX/SASS 与改前逐字节相同**（纯编译期改写）；**红** = ①改后核函数数量/模板实例数变了（说明写错了实例）②MSVC 仍报 C2326（说明还有捕获点没扫干净）。

### P-02 · C3495：`[&]` **简单捕获**外层泛型 lambda 里的 `constexpr` 局部（**2 个文件，2 处**）

- **病根**：`constexpr` 局部变量**声明在泛型 lambda 内**，被更内层的 lambda 以 `[&]` 捕获并**用作模板实参/属性值** ⇒ MSVC 报 C3495。
- **修法（两种，他们各用了一种）**：
  1. `src/ops/gdn_gating_proj/bf16/bf16_gdn_gating_proj_kernels.cu`（`~:297`）：把 `configure_cuda_device_once([&]{ … <…, FullTokens, …> …})` 改成 **`if constexpr (FullTokens) { configure_cuda_device_once([]{ …true… }) } else { …false… }`**，回调改**空捕获 `[]`**（同一 kernel 特化、同一 once-per-device 缓存）。
  2. `src/ops/softmax_attention/dense/causal_cache/small_t_i8_launch.cuh`（`~:44`）：**删掉 `constexpr std::size_t kDynamicBytes = …` 这个局部**，两处用它都改成**常量表达式** `DynamicArena ? static_cast<std::size_t>(4 * KeyBlock * kCausalHeadDim) : 0u`（`DynamicArena`/`KeyBlock` 都是模板参数 ⇒ 编译期折叠；回调改空捕获 `[]`）。
- **判据**：**绿** = MSVC 编过 + 启动/冒烟不变；**红** = ①动态共享内存属性没设上（表现：`cudaFuncSetAttribute` 失败或 kernel 启动报 shared memory 超限）②同上，C3495 仍在 ⇒ 还有第二处捕获。

### P-03 · C2026：单个字符串字面量超 16380 字符（**1 个文件，CMake 侧**）

- **我们**同样暴露 **（`A` 级实测）**：`src/runtime/engine/device_profiles.json` = **30,566 字符**（与他们那个数**一模一样**）⇒ 超过 MSVC 的 **16,380** 上限。
- **他们的修法**（纯 CMake，不动 `.cpp.in` 模板）：`src/runtime/CMakeLists.txt` 在 `file(READ … NINFER_DEVICE_PROFILES_JSON)` 之后加一段循环：`string(LENGTH …)` → `_chunk_size = 16000` → `while` 循环用 **`)ninfer_json" R"ninfer_json(`** 把相邻 raw string 拼接起来 → `set(NINFER_DEVICE_PROFILES_JSON "${_json_parts}")`（**字节不变**，分隔符串在 JSON 里不出现 ⇒ 无碰撞）。
- **我们要不要抄？** **看工具链**：我们 B23 已测 —— **MSVC 19.44 会报 C2026，19.51 全量构建通过**（新版上限放宽）。⇒ 这条对我们是**"给别人编"的保险**（谁用 19.44 谁撞），**不是我们自己构建的阻塞项**。
- **判据**：**绿** = 19.44 下编过且 `device_profiles_builtin.cpp` 里的 JSON 字节与 `device_profiles.json` **逐字节相同**（拼接没吃掉字符）；**红** = ①JSON 被截断（比对长度/哈希）②分隔符串出现在 JSON 里（会撕开字面量）。

### P-07 · 两条构建纪律（无代码，照写进我们的构建文档）

1. **`.bat` / `.cmd` 注释一律 ASCII-only** —— cmd 按 OEM/ANSI 码页解析，中文注释会乱码并炸构建（他们的血泪）。
2. **产物与中间目录不许混**：编译产物（exe + DLL）必须落正式目录；构建中间目录只放中间物。
3. （顺带，`A` 级核到的机制）**`NINFER_BUILD_ID` 可覆盖版本串**：`cmake/GenerateBuildId.cmake` 默认用 `git describe --always --tags`；设了该环境变量则**直接以之为 base** ⇒ 剥平前缀/无 tag 血统的树靠它自定义版本串。

## §2 移植配方（命令级；**含备份与回滚**）

> 纪律：改前备份（含二进制）· 只改我们的隔离副本 · 一次编译原则（把 P-01/P-02/P-05 合进同一趟）· 判据先写死。

```powershell
# 0) 干净基准（可选，用于先验补丁）：在 tag 2852f6f 上开一个临时 worktree
git -C <我们的仓> worktree add --detach E:\infer-build\tmp-wt-2852f6f 2852f6f

# 1) 补丁 CRLF→LF（关键！否则 git apply 报 "patch does not apply"）
$lf = "$env:TEMP\0001.lf.patch"
[System.IO.File]::WriteAllText($lf, ([System.IO.File]::ReadAllText($p1) -replace "`r`n","`n"), (New-Object System.Text.UTF8Encoding($false)))

# 2) 先 check 再打（在目标树上）
git apply --check $lf          # 期望 rc=0
git apply --stat  $lf          # 看文件级摘要
git apply $lf                  # 真正落盘（改前已备份）

# 3) 回滚
git apply -R $lf               # 或直接 checkout 备份/还原那 10 个文件
```

**顺序建议**：`P-01 + P-02 + P-05`（纯编译期/构建开关，**一趟编**）→ `P-06`（全树扫，同一趟一起改）→ **`P-03`（只在需要兼容 MSVC 19.44 时才上）** → `P-04`（**行为改动，单独一趟 + 开关 + 负控**）。
