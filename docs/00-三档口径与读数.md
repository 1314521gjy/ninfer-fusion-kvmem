# 00 · 三档口径与实测读数

**口径**（三档完全相同，可直接横向比）：引擎 = 本包 `engine\ninfer-serve.exe`（sha256 `CFE56FFB…887`，sm_89）；
参数 = README §4 那段（`k8v4` / 池 17,920 / 窗口 16,384 / 宿主 16 GiB / `dflash2 draft4` / 单路）；
题面 ≈ 1,100 token，输出上限 96 token，非流式；卡 = RTX 4080 SUPER 32 GB（每档开跑前显存基线 ≈1.0 GiB）。

## 3. 长上下文与"每轮不重填"（PQ2 档实测）

| 轮次 | prompt | 复用 | 首 token | 墙钟 | 结果 |
|---|---|---|---|---|---|
| A 冷启动 | **80,063 token**（远超 16,384 常驻窗口） | 0% | 70,829 ms | 71.2 s | 题面**正中**的针被答对 |
| B 同一会话第二轮 | 新算 **27** token | **100%（cache 80,075）** | **126.5 ms** | 0.4 s | 针仍答对 |

⇒ 这条是"**小池 + 长上下文 + 每轮不全量重填**"三条同时成立的判据；机制与五个开关见 README §4、§5 第 3 条。

## 4. 怎么自己复现这组数

```bat
:: 起档（改好路径与端口）
start-pq2.bat
:: 打个短请求看 decode（响应里 timings.predicted_per_second 就是 decode）
curl.exe -s http://127.0.0.1:8091/v1/chat/completions -H "Content-Type: application/json" ^
  -d "{\"model\":\"qwen3.8-27b\",\"messages\":[{\"role\":\"user\",\"content\":\"Count from 1 upward, one number per line, and nothing else.\"}],\"max_tokens\":96}"
```

判据三件套：① `/v1/models` 200 且 `context_window=262144`；② 启动日志有 `capacity | KV 17,920 tokens, k8v4`；
③ 请求响应里 `timings.predicted_per_second` 与上表同量级、`usage.completion_tokens` 与 `max_tokens` 相符。
