# docs 目录说明（**口径分层**）

本目录混着两批文档，读之前先分清：

| 批次 | 文件 | 口径 |
|---|---|---|
| **当前口径** | `编译指南-怎么编.md`（仓根）· `README.md`（仓根）· `NOTICE.md`（仓根）· `已知问题-初期版本.md`（仓根）· `实测回执与反馈.md`（仓根） | 与当前源码树、当前发布件一致；**冲突时以仓根这几份为准** |
| **历史口径** | `00`–`06`、`08`、`09`、`11`、`12`（**没有 07 / 10**）、`判据.txt`、`方案/` | 写于早期分发包阶段：里面的**数字、文件名、路径、批次结论**都是**当时那批包**的读数，机换了/包换了就不适用；机制与排查思路仍然有效 |
| **参考件（第三类）** | **`13`**（对标件）· **`14`**（可移植清单） | **既不是"当前口径"也不是"历史分发包口径"**：写的是**外部工程**（同源兄弟件 / 下游工程）与我们的差异、可抄项、判据；其中的**外部读数一律 C 级**（他人自报），我方读数按仓内账本等级 |

**`13-对标-同源兄弟件-KVMem-RC2-调优方向-20261009.md`**：把同源兄弟件（`kvmem/kvmem-llama.cpp` RC2）**比我们好的地方逐条落成方向**（D-01…D-08，每条带判据与"怎么变红"），含两条**零成本先做**（抬 sink = 消 B34；抬输出上限 = 消 B37）。

**`14-可移植清单-下游工程paicat1-20261010.md`**：把下游工程 `paicat1/Bonsai-27B-NInfer-kvmem` 对我们的 3 组补丁（10 文件）**逐条拆成 P-01…P-08**（改哪个文件、before→after、判据、怎么变红、成本、风险）。两条实测要点：① **那 10 个文件在我们树上 `git apply --check` 全过**，但前提是**补丁要先 CRLF→LF**（他们的补丁是 CRLF，直接打会假报 `patch does not apply`）；② **同类 MSVC 模式他们只修了一部分**（`cudaFuncSetAttribute(kernel` 全树 13 个文件里只修 1 个）⇒ 移植时要全树扫。

引用纪律：历史口径里的读数**照用前先复核**；涉及许可/署名的内容一律以仓根 `NOTICE.md` 为准。
