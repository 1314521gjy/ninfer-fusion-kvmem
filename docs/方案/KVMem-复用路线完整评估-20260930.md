## §0 一句话

**"池 ≥ 前缀"是两条树、四类实现共同的硬前提** —— 旧主线（I 树）跑通的 99.7%/99.9% 复用，全部发生在池 ≥ 前缀的档位（262k 用 4,096 页、65k 用 1,024 页）；我们在 master 基座上独立复现了同一条规律（`S3b` 99.9% / 116 ms）。
**要打破它，只有一条路线在结构上成立：把 KV 的权威副本放到 tier 上、设备只保有界工作集、每次重选只搬差量** —— 这就是上游 `kvmem-qw3` 的 P2 路线（④）。它储备最全（策略层实现已在树 + 官方 host 判据全绿），但它背着一个**官方自标未解的算法问题 KVMI-012**，因此"**完全不重填**"在混合 GDN 模型上会退化成"**少重填**"。
**在 ④ 之前有一条更短的路**：**③ 让"领用"也按需**（惰性 materialize）——它不引入新机制（环在**同一会话内**本来就是这么干的），**不需要新内核**，判据现成。

## §2 优势（④ 为主、③ 为辅）

1. **结构上唯一能打破"池 ≥ 前缀"的设计**：KV 权威在 tier（GPU / pinned host / NVMe 接口），设备只保有界的**组装工作集**，每次重选只搬**差量**（`stage_in` / `stage_out`），已在卡上的块**免搬**（`gpu_reused_blocks`）。①②⑤⑦ 都不动这条前提，⑥ 只是"少搬一点"。
2. **储备最完整，几乎不用从零**：
   - 策略层**实现已在树**（`qw3\kvmem_store.hpp` / `kvmem_gc.*` / `kvmem_refresh_policy.hpp` / `kvmem_prefix_reuse_policy.hpp` / `pinned_kv_tier.hpp`），带 Apache-2.0 归属头；
   - **官方 host 判据 11 份全绿 + 6 份负控有牙**（纯 host、无 GPU，可直接当回归网）；
   - 接入点总表 / 落点勘察 / 接线任务书 / 判据台接口需求 / 分叉决策记录**全在**（`03-规格与设计\KVMem-*`）。
3. **质量方向有实测支撑**（非论文转述）：官方实现在我们机器上 55K 三针：**检索 9/9 vs 不检索(recency) 4/9**；**128K 档只用 27% 预算也 3/3**；且**官方 sink 公式在我们 `block=64` 下不够**（`clamp(1%×budget,1024,2048)`⇒2048 在 55K 与 128K **两档都失败**；**≥4096 才稳**）——这条已被我们独立复现两次。
4. **与既有构件同构**：页池 + 页表 `publish`（乱序已实测）、`HostKVArena`（**底层已是 pinned**，正是 KVMI-011 要的"大块 H2D"前提）、`StateImage`/`HostStatePool`、压力驱动 `stage_out`/`stage_in`（老主线已接线）。
5. **它是"低显存分支的成立条件"而非优化项**（立项原文）：三元制品 7.74 GiB 时，8 GB 卡只剩 0.3–1 GiB 给 KV+工作区 ⇒ 按 fp8 ≈16.95 KB/token，**常驻只能 16K–60K** ⇒ 不压常驻就没有长上下文（`03-规格与设计\三元引擎-优化路线总表…:323`）。

## §3 劣势 / 风险（按严重度；每条给出处）

1. 🔴 **KVMI-012（P0 / RESEARCH，官方自标"算法未解"）**：混合 GDN 模型（我们 16 全注意力 + 48 GDN）下"**被选中的注意力窗口**"与"**累计的递归态**"描述**不同历史**。官方"最终候选"= 保留 8 个稳定 sink 块 + 对 **top-1024（32K）源 token 做一次源序 fresh prefill**（`kvmem_known_issues.md:461-462`）。
   ⇒ **后果直接打击我们的第一目标**：混合模型上"**每轮完全不重填**"做不到，最好情况是"**只重放被选中那一段（32K 量级）**"—— 40k 提示约 15 s，比现在 20.7 s 好，但**远不是 116–199 ms 那一档**。
   ⇒ 而且**没有任何人做过"任意块子集 + 混合状态"**（HYPIC 只做连续段、Tail-Replay 只做连续前缀）⇒ **判据要我们自己造**（`KVMem-接线任务书…:431`）。
2. 🔴 **KVMI-011（fp16/fp8 原地 re-RoPE 累积漂移，P0/IMPLEMENTED）**：阈值 **8 次累积旋转或累计位移 ≥262144**；**fp16 连续 32 次原位 re-RoPE 在 temp=0 下把正确样本答案从 `1` 改成 `0`**。逃生阀 = **不可变 raw-K 影子**，代价 **fp16 raw-K ≈8 GiB / 256K**（或每 token 67.3→35.3 KiB 的取舍换窗口 60K→115K）。
3. 🟠 **KVMI-011A（MTP 位置语义）**：**逻辑位置**（可到 1M）与 **RoPE 位置**（紧凑窗口坐标，必须 `< n_ctx_train`）**显式分离**；硬约束 **`kvmem_budget + gen_budget ≤ n_ctx_train`**；**MTP prefix 必须在 RoPE 前抓 raw-K**、draft chain 按剩余紧凑位置动态截断。⚠️ **我们跑 `--draft-tokens 3` ⇒ 直接适用**。
4. 🟠 **检索不是免费的**：同预算下**每次请求多花 1,860–3,475 ms**（`recency` 路径为 0）(`KVMem-试驾…:140`)。
5. 🟠 **内核适配**：re-RoPE 要支持我们的 `Fp8E4M3Row256`（256 B + **每向量 1 个 FP16 scale**），而官方三份内核是 **raw e4m3、无 scale** ⇒ 属**新工作**（数学体同构，layout 要重写）。
6. 🟠 **工作量**：**3.5–6.5 天到"端到端能跑"（先不接检索）**；真正要自己趟的只有三样 —— ① KVMI-012 的正确性判据 ② 我们引擎里的落点/捕获/arena 约束 ③ sink 门槛与我们口径的复验（`:437`）。MTP 是独立第三段（2 个落点、形态不同）。
7. 🟡 **有损近似**：掩码/检索的可见范围是**近似**；且**"常驻≠可见"**（试驾实测每格 mask 完全相同而结果不同，逐块明细不报）⇒ 必须有我们自己的可见性 trace 判据。
8. 🟡 **配置陷阱已实测两条**：sink 吃满预算 ⇒ **请求直接 HTTP 500**；`sink=0` 语义 = "保留 1 块"（长上下文里等于不保护）。

## §5 结论与建议顺序

**建议：① 锁基线 → ③ 破墙 → ④ 提效（在 ③ 的判据台上做）。**

1. **① 今天就能锁**（`S3b` 口径）：池 ≥ 前缀 = 99.9% 复用、116 ms、2.44 GiB@40k。这是**可用形态**，也是 ③ 的对照臂。
2. **③ 是"破墙"的最短路径**（中等工作量、无新内核）：把复用激活从"整段 materialize"改成"整段登记 + 逐块 materialize"。
   - 首个臂的建议配置：池 ≈ **窗口(8192 tok=128 页) + sink(4096=64 页) + 检索预算** ⇒ **192–256 页（≈0.7–1.0 GiB）**，而不是 16 页（16 页时检索预算只有池/4 = 4 页，可见范围太小，读数会假阴）。
   - 判据：`S3a2` 500→200；turn2 `cache > 0`；**针测两轮命中**（两轮 = 覆盖"混合 GDN 第二次复用才炸"这条已知雷）；`Paged KV reservation invariant` 不再出现；`S3b` 不退化；OFF 臂逐字不变。
3. **④ 只在下列任一成立时上**：③ 的质量/延迟不够；或要 8 GB 卡档；或要 1M 级可寻址 workspace。
   - ④ 的第一刀按官方 §7 与我们任务书 §7 的建议：**有界窗口 → sink 保护 → 压力/最新优先**先跑最小形态，**把检索打分做成可插拔升级**（省掉 mean-K/Eq.10/视图组装的一部分）。
   - ④ 的三条红线必须同时成立才准放行：**sink ≥ 4096 token**、**sink 显著小于 budget**、**`kvmem_budget + gen_budget ≤ n_ctx_train`**。
4. **⑤ 磁盘层不参与破墙**（同一天花板），仅作"跨重启/被驱逐会话持久化"；⑥ 快照+回放是 ① 的"省内存版"，24× 提速的账已算过，可作 ③ 之外的第二备选。
