# 立项 · 思维链调优（Chain-of-Thought Tuning）—— 死亡循环与思考期行为

> **建立**：2026-09-30 ｜ **决策记录**："把死循环问题单独立一项，这一项的内容就是思维链调优。我们后期会出一个专门对它（的）项目研究。"
> **本文件是纲领，不是结论**：已定的写"已定"，没定的写"待研究"。所有读数带证据路径。
> **为什么单独立项**：这不是"某个旋钮没调好"，而是**模型家族（Qwen3.5/3.8）+ 采样规格 + agent 回灌方式**三者交叉出来的一类失败；它同时牵动我们的**交付（§8 已写进包）**、**引擎（是否要加惩罚窗口/预算策略）**与**平台（监督护栏）**三层。

---

## 1. 一句话

**思考开着跑长循环时，模型会进入"重复/自旋"状态：轻则反复念同一句计划（空转），重则连续多轮不产出任何交付物；而引擎层全程零报错。** 官方仓库承认该现象存在且**未修**，社区给出了三条缓解路径（不回灌推理、注入预算+惩罚、限定惩罚窗口）——**根因未解，缓解在平台侧**。

## 4. 已定 vs 待研究

**已定**
1. **思考关**：12 轮自主循环**0 次退化**，且复用稳定 99.0~99.9%（到 9.4 万 token）。⇒ **本档发货配置（`--no-thinking`）天然躲开"无产物"那一类退化**。
2. **思考开 + 预算每轮打满 + 回灌推理**：**必然**进入退化（连续 10 轮）。
3. **`--presence-penalty 1.0` 不能治愈**（间歇 6/12 轮），但**速度无可见代价**（312~358 vs 386~524 tok/s）。
4. **投机解码不是成因**：停滞那场用的是 **MTP draft 2**（最保守档），且"逐字相同的固定点"不是数值翻转能解释的。
5. **退化不是记忆问题**：跨窗口检索与自述历史在退化期间仍然正确。
6. **复用与思考耦合**：思考开 + 预算打满 ⇒ 复用两态跳变（亚秒 ↔ 3.4~16 s）；**根因未定**（"预算控制 token 客户端复现不了"是候选解释之一，与"response replay 路径"读数一致，但未隔离）。

| **RQ6** | 与**推测解码**的交互：MTP/DFlash2 的近似并列翻转是否改变退化概率（引擎文档承认推测路径与原路径**不逐位相同**） | 只有"不是主因"这一级证据，**未量化** |
| **RQ7** | 与**上下文/复用**的交互：能否让"思考开"也保持 99% 复用（不回灌推理是否已经把这条修好？—— A2 会顺带回答） | A2 在飞 |
| **RQ8** | **官方 API vs 本地部署的行为差异**：为什么官方 API 少见？服务端到底托管了哪几件事（`thinking_budget` / 采样默认 / 推理回灌口径 / 是否还有别的）？**我们的引擎该不该把这几件事也托管掉**（例如"思考模式下自动补 presence 1.5 + 惩罚窗口"） | **未开工**；线索：DashScope 有 `thinking_budget`；我们的引擎已有预算与 `</think>` 收尾，**缺** presence 默认与惩罚窗口 |
| **RQ9** | **同族横扫（族级 vs 制品特有）**：手上 5 件同族制品（三元 PQ2 / GSQ IQ3_S / GSQ+dflash2 / Swift-RCO IQ3_S / Swift Q4_K_M）用同一停滞剧本各跑 10 轮 | **决策记录（2026-09-30）：不扫**——"整个族确实都是这样，我基本上都体验过"；但**用户第一手：Bonsai（三元 PQ2）出现频率明显更高**（与我方基线 10/10 轮退化一致）。⇒ 改为**记录用户观察**，不再花机时 |
| **RQ10** | **不回灌推理会不会伤后续工作（工作连续性/自纠能力）？** | **已有强证据（2026-09-30，A2 前 4 轮）**：`stall-A2-noecho` —— **4 轮 4 个互不相同的自选优化项**、每轮实质改动（`changed` = 685 / 569 / 625 行）、**第 4 轮主动揪出并修自己上一轮引入的回归**（原文："上一轮的车身几何完全散乱（车座没有坐标、鹈鹕与车体脱节、wheel 被误套入 bike class）"）⇒ **工作连续性、自纠能力都不依赖回灌推理**。对照 A1（思考关，本就无推理可灌）：12 轮工作也连续，但**同一自选计划重复 9/11 轮**（病 B）——A2 反而 4/4 不重复。**规格侧**：hermes-agent 指出 Qwen 多轮规格**禁止**回灌 ⇒ **不回灌才是"照规格用"**。<br>**代价（如实）**：本引擎上不回灌时**复用从 ~99.9% 掉到 ~55%**（引擎把"客户端重放的响应"认成自己的记录；不回灌只能命中上一轮 prompt，TTFT 3.7~4.8 s）⇒ 这是**引擎复用匹配口径**的问题，已登记为 **G23** |
| **RQ11** | **"留推理"的正确姿势**：不灌原始 CoT，改让模型把关键决定**写进答案**（我们已在用 `OPT:`/`STATUS:` 这种"决定日志"），或客户端把上一轮推理**摘要成几行决策记录**再放回上下文 | **未开工**（可作为平台护栏的一部分；判据：与"回灌原始推理"对照，看退化轮数与工作连续性） |

## 5. 判据（可执行，照用即可复跑）

- **主判据（"无产物"）**：12 轮自主循环内，**无产物轮数 = 0**，且**最长连续无产物 = 0**。
  基线读数：**10 / 10**；A1：**0 / 0**；A6：**6 / 6**。
- **次判据（"空转"）**：同一自选计划（`OPT:` 行归一化后）**重复次数 ≤ 2**。基线 ×8；A1 ×9（11 轮内）。
- **固定点指纹**：连续两轮答案**逐字相同** ⇒ 判为固定点（基线第 11~18 轮 7/8 轮逐字相同）。
- **负控（仪器必须能变红）**：① 用**基线配置**跑同一剧本必须复现退化（已复现，n=2 场）；② 用 **`--no-thinking`** 跑必须为 0（已读 12/12）。
- **成本判据**：decode tok/s 与推测接受率（`ngram/mixed`）——用于确认"缓解手段不是拿速度换的"。
- **证据口径**：所有读数取自引擎自己打印的 `req#N done` 行与驱动逐轮 `turns.jsonl`；`presence_penalty` 一类开关必须写进 `arm-metadata.txt` 的 argv。

## 11. ★ 判断 H1：**思考长度就是这个模型的智力来源**（2026-09-30）

> （此处原有需求方的口头表述，已按发布口径删除；结论：不要把思考预算压得过低）

### H1 的支持证据（我方四臂，全部可复算）

1. **思考预算在我们每一场里都是"紧的"**：基线/A2/A6 给 1,500 ⇒ **每轮都用满 `1,500/1,500`**；A7 给 8,192 ⇒ **每轮都用满 `8,192/8,192`**。⇒ **模型每次都想用更多：我们一直在削它。**
2. **削思考的两个可测代价**：① **半截**——思考 token **也占 `max_tokens`**（帮助原文 *"control tokens count toward the output limit"*）⇒ A7（思考 8,192 + 上限 12,000）**12/12 个产物全写不完**；② **推理被生硬切断**——引擎在预算处注入控制 token 并补规范 `</think>`，这既伤复用（前缀断在思考边界），也让"计划"停在半句上（基线退化段每轮思考恰为 1,500/1,500）。
3. **反向对照**：**思考关（A1）虽 0 次空交付，但病 B 最重**（同一自选计划重复 **9/11 轮**），且完全没有推理能力 ⇒ 与"砍思考 = 降智"一致。

### ★ 关键推论（好消息）：**放开思考与防自旋并不冲突**

**A2 的证据**：它**每轮照样把预算打满**（`thinking 1,500/1,500, control 25`），却 **0 次空交付**（10 轮，答案 15k~24k 字符）。
⇒ **防自旋靠的是 `F1`（不回灌推理），不是压思考上限。**
⇒ **所以可以把思考放开（给足或干脆不设），同时保住 0 自旋**——"智力"与"稳定"**不必二选一**。

### 放开思考必须配套的四件事（否则会从别的轴漏出去）

| # | 配套 | 判据 / 反例 |
|---|---|---|
| 1 | **`max_tokens` ≥ 思考 + 交付物**（想超长思考又要完整文件 ⇒ 给到 32k 级） | 反例：A7 思考 8,192 + 上限 12,000 ⇒ **12/12 半截** |
| 2 | **别用"每轮必满"的小预算**：给足让它自然 `</think>` 收尾，或不设 | 反例：1,500 每轮用满 ⇒ 推理每轮被切一刀 |
| 3 | **护栏（F2）兜底**：三态判据（空交付 / 半截 / 固定点）+ 重试 | 反例：A7 放开后**仍有 1/12 空交付**（`finish=stop`、预算未满、答案 0 字符） |
| 4 | **认代价**：超长思考 ⇒ 单轮慢（思考段 decode **70~130 tok/s** vs 答案段 **300~520**）、上下文消耗大（思考 token 占 KV、挤压窗口与复用） | 读数见各臂 `engine.err.log` |

### 待测实验（把 H1 从"经验"变成"读数"）——**立项第一优先实验**

同一剧本（现有 `longburn` 臂即可）、**`max_tokens` 给足 40k**，只改思考预算跑三档：
① **1,500（削）** ② **8,192** ③ **不设上限**（自然收尾）。
**质量电池**（每档都算）：结构约定保留数 · 自选计划新鲜度（逐字/主题两级）· 自修质量（是否揪出自己引入的回归）· **产物完整率** · 跨窗口复述命中 · 空交付轮数 · 单轮耗时与 decode。
**预期（H1 若成立）**：质量随思考长度单调上升，而空交付轮数**不随之上**（因为 F1 已把自旋轴关掉）。**这个结果将直接决定分发包的推荐配置。**
