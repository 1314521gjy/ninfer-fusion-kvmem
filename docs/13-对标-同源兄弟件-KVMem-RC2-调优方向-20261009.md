# 对标 · 同源兄弟件（KVMem RC2）与我们的差异 ⇒ **我们的调优方向**

> 立项 2026-10-09。**来源两份一手材料**（C 级，外部自报）＋ 我们自己的账本/实测（A 级）。
> **本件只做两件事**：① 把他们做得比我们好的地方**逐条落成方向**；② 每条给**判据与"怎么变红"**、**成本**、**落到哪个文件**。
> ⚠️ **别混线**：本件是 **B 线（我们自己的引擎 ninfer 融合件）** 的对标件。A 线那份《Strata 调优回执》是**另一条线**（Strata 引擎的调参效果），两者不是一类东西。
> 一手材料：**RC2 发布页** <https://github.com/kvmem/kvmem-llama.cpp/releases/tag/v0.18.0-ninfer-rc2> ｜**issue #113** <https://github.com/kvmem/kvmem-llama.cpp/issues/113>

## §1 关系判定（一句话）

**同一个 KVMem 血统，两个不同内核底座**：他们 = `iamwavecut/ninfer-all`（多分支整合）+ KVMem，做**Windows 预编译整合包**；我们 = 自己的 `fusion-engine-src` 融合树，出**源码 + 三档清编件 + 账本**。
**而且他们点名适配我们**（GGUF 仓专为我们发 Q8MTP 包，因为"社区分支 ninfer-fusion-kvmem 读不了 Q4_0 格式的 MTP 头"）⇒ 我们是他们生态里被承认的一支，**但他们不是从我们的树编出来的**（其致谢名单无我们）。

## §2 他们的优点 ⇒ 我们的方向（总表）

| ID | 他们怎么做 | 我们现在 | 我们要做什么 | 判据（**怎么变红**） | 成本 | 关联条目 |
|---|---|---|---|---|---|---|
| **D-01** | 默认 **sink/recent = 5120/5120 tokens** | `NINFER_KV_SINK` **默认 4 页 = 256 token** | **启动器里把 sink 抬起来**（不改源码默认值） | banner `[ring] budgets: skeleton=<80 页>` 出现且守卫生效；**红**：抬 sink 后撞 `sink + 4 ≤ pool` 启动即拒，或深层针 TTFT 不降 | 极低（一行 env） | **B34** |
| **D-02** | 默认输出上限 **16k** | `--default-max-tokens` **默认 8192** | **启动器里抬到 16384/32768** | 不带 `max_tokens` 的请求：`requested_output_tokens_source=server_default` 且能吐 >8192、`finish_reason=stop`；**红**：仍断在 8192（开关没生效） | 极低（一行开关） | **B37** |
| **D-03** | host KV payload 预算 **12 GiB**（默认给出） | `--host-kv-mib` 按档手配 | 出一张**按卡/按内存的 host 预算表**并写进启动器 | 启动守卫不拒 + `/stats` 里 **host 页数 ≥ 逻辑页 − 池页**；**红**：8G 机器内存不够却照抄 12 GiB | 低（文档+启动器） | 调优方案 §1.5 |
| **D-04** | **一键包 + Web UI**（解压即用，18200 端口） | exe + 文档 + `start-8g.bat`，**无 UI** | **只把"一条命令 + 就绪自证"做齐**（不做 UI） | 新机器照 README 数分钟内起服务并有就绪自证行；**红**：需要人肉排错才起得来 | 低 | `12-给接收方-agent 的操作手册` |
| **D-05** | **多卡按层分配**为一等公民（8 卡、自动分配、`-StageLayers 40,24`、双卡已验证） | 源码里有 `--devices` 跨卡专家/层切分，**发布档以单卡为主** | 把多卡分层**启动器化 + 文档化 + 给一条双卡判据** | 双卡按层分配后文本请求 200 且层数合计 = 模型层数；**红**：分配数与层数不等，或单卡路径行为被改动 | 中 | `--devices`、pipeline-parallel 计划 |
| **D-06** | 位宽覆盖最宽：**Q2_0 / Q4_0 / Q5_0** + 9 种 KV | **3.4 bpw 附近是空的**（Q4G64 4.25 / 三元 2.125） | **新增 ~3.5 bpw 档**，或至少在文档给"要小用三元、要无损用 Q4G64/NVFP4"的决策表 + 明写缺口 | 同模型同卡：3.5 bpw 比 Q4G64 少 20–25% 字节且质量在噪声带内；**红**：质量掉出噪声带 | 中—高（要转档+验收） | 位宽缺口（本项目 §3 F8） |
| **D-07** | 他们**也没解决**工具调用（issue #113：DSH/workbuddy/pi 三例；维护者称下版并入上游补丁）——但**默认 sink 大，天然躲开** | **B17 未修**（"待查，疑模型/提示词层"） | 三件一起做：① **把工具定义段钉进 sink**（正是 sink 的语义）② **容错解析**（学 `--tolerant-tool-calls`）③ **坏样本可计数、不许静默中断** | 同一夹具（长上下文 + 多轮工具续写）坏样本率下降或至少**可计数**；**红**：坏样本率不变 ⇒ 机制不在我们猜的那条路 | 中 | **B17**（+ §4） |
| **D-08** | 跑过**同形态续航验收**：256k / **33 请求 / 32 个工具轮全过** / 前缀命中 32/32 / 淘汰 0 次 | 我们**缺一条同形态的验收臂**（长上下文 + 多轮工具续写） | 建这条臂（见 §6） | 逐轮给出 **TTFT / 前缀命中 / 淘汰数 / 显存峰值** 四项；**红**：任一轮失败，或淘汰数 ≠ 0 且未解释 | 中（占 GPU） | 新 |

## §3 零成本先做（两条，都是启动器层面，不碰源码）

### 3.1 D-01 抬 sink（消 B34 那条悬崖）

- **落点**：`start-8g.bat`（及我们给各档的启动器）加一行 `set NINFER_KV_SINK=5120`（先 5120；8G 档池 1,038 页对 80 页 sink 有富余）。
- **为什么是启动器而不是源码默认值**：源码默认 `4U` 页是"最省显存"的取向，改它等于**改所有档的行为**；我们要的是"**默认档就安全**"，不是"把小卡也撑爆"。
- **判据**：banner 出现 `[ring] budgets: skeleton=80 …` 且 `free` 不减到守卫线下；**变红**：① 撞 B21 守卫（`sink + 4 ≤ pool`）启动即拒 ② 深层埋针 TTFT **不降** ⇒ 说明这条不是 sink 的问题，回退预案 = 删掉这行。
- **依据**：官方 RC2 实测 **sink 0 → 10240 把"最深埋针取回"从 221.66 s 降到 1.4 s**（A/C 级，见 `实测回执与反馈.md` §17）。

### 3.2 D-02 抬输出上限（消 B37 的级联）

- **落点**：各档启动器加 `--default-max-tokens 16384`（或 32768）。
- **判据**：不带 `max_tokens` 的请求能吐 >8192 且 `finish_reason=stop`（B37 那条实测：32768 ⇒ 吐 23,893 token 且 stop）；**变红**：仍断在 8192 ⇒ **先怀疑开关没生效**。
- **回滚**：删开关即回默认（8192）。

> 这两条**都不需要编译**，改的是启动器；**改前备份**，并在 README/排错手册里各留一行"为什么这么设"。

## §4 中等成本（三条）

1. **D-07 工具调用三件**：
   - **①工具定义钉成骨架**：工具 schema 永远在提示最前面，天然属于 sink 语义 ⇒ 先靠 D-01 的 sink 抬高拿到第一手读数（**零额外成本**）。
   - **②容错解析**：参考 `sergiuszm/ninfer-4090` 的 `--tolerant-tool-calls`，与 **Strata 0.1.41** 的 "`<function= NAME>` 按 NAME 解析（#1430）" 同族做法 —— **只做"能读回来"，不改模型行为**。
   - **③坏样本可诊断**：坏的工具调用必须**落日志 + 可计数**（现在客户端侧是"**会话中断**"，这是最坏的失败形态）。
2. **D-05 多卡分层启动器化**：把 `--devices` / stage-layers 变成启动器一等参数 + 一条双卡判据（层数合计必须等于模型层数）。
3. **D-06 ~3.5 bpw 档**：成本最高的一条（要转换 + 质量验收）；**建议先只做文档决策表**，把"什么时候用哪档"写死，转档留到有明确需求时再做。

## §5 我们该守的（**不做无用功**）

1. **可读的失败形态**：429 + 编号报文 + 进程存活 + 计数器 + 启动守卫拒启（B01/B21）。他们那边只能靠猜"KV 缓存丢了工具定义"——**这正是我们不做的事**。
2. **盘级 KV 层**（`--disk-kv-path` 等）：他们的 KVMem 文档**明写 NVMe offload 未实现**。
3. **账本纪律**：每条问题带判据 + 怎么变红 + 归属件（预编译包结构上做不到这件事）。

## §6 建议的验收臂（D-08 的具体设计）

**目的**：把"我们能不能像他们那样，在长上下文里连续跑几十个工具轮而不掉链子"变成一条可重复的读数。

| 项 | 设计 |
|---|---|
| 题面 | ≥ 30,000 token 的中文/代码混合题面 + **工具 schema**（工具定义放最前，正是被换出的高危段） |
| 轮数 | 20–32 轮工具续写（每轮新增 ~8k 上下文，对齐他们的口径） |
| 记录四项/轮 | **TTFT** · **前缀命中** · **淘汰数（evictions）** · **显存峰值** |
| 对照臂 | ① `NINFER_KV_SINK` 默认(256) vs 5120 ② 检索开 vs 关 ③ `--default-max-tokens` 8192 vs 32768 |
| **判据（绿）** | 全部轮次 HTTP 200、**零坏工具调用**（或坏样本可计数且不中断会话）、淘汰数 0 或有解释 |
| **变红** | ① 任一工具轮出现 `<|im_start|>…` 式坏工具调用且会话中断 ② 抬 sink 后坏样本率不变 ⇒ 假说不成立 ③ 淘汰数非 0 且命中率崩 ⇒ 池/窗口配错 |
| 成本 | 一轮 GPU 作业（按纪律：先断言无残留引擎、端口空闲、显存够；**同时只起一个**） |
